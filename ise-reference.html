01Architecture and personas

ISE is one product running several roles. Interviewers almost always open here, because how you describe the personas tells them whether you have run a real deployment or only read about one.

Persona role a node plays

A single ISE node runs one or more personas. The persona decides which services start and which traffic the node handles. A node can change persona, but only after it is registered into the deployment, and changing it restarts services.

PAN Policy Administration Node

The single configuration plane. Every policy, network device, certificate and identity-store change is made on the Primary PAN, which then replicates the configuration database to every other node. A deployment has at most two: Primary and Secondary.

If the Primary PAN is down you can still authenticate — PSNs keep serving from their local copy — but you cannot make configuration changes, and some functions that need a write to the central database (guest account creation, BYOD registration, internal endpoint updates) are affected.

Interview angleBe ready for “what breaks when the PAN dies?” The answer is configuration and anything requiring a central write, not authentication.

MnT Monitoring and Troubleshooting Node

The logging and reporting engine. PSNs send syslog to the MnT nodes, which populate Live Logs, Live Sessions, reports and alarms. Maximum of two, Primary and Secondary. In a deployment with two MnT nodes, PSNs log to both, so each holds a full copy.

MnT is the heaviest consumer of disk I/O in the deployment, which is why sizing and log-retention settings matter and why a busy deployment separates MnT onto dedicated nodes.

PSN Policy Service Node

Where the actual work happens. PSNs terminate RADIUS and TACACS+, run the EAP state machine, evaluate policy, host guest and client-provisioning portals, run the profiler, and issue CoA. These are the nodes your network devices point at. A large deployment supports up to 50.

pxGrid node context-sharing controller

Runs the pxGrid controller that publishers and subscribers connect to for context exchange. Up to four in a deployment, configured active/standby for high availability.

Deployment models

  • Standalone — one node running all personas. Lab and very small sites.
  • Basic two-node — two nodes, each running all personas, one primary and one secondary for each. Redundancy without separation.
  • Hybrid / medium — PAN and MnT combined on two nodes, with dedicated PSNs behind them.
  • Large / dedicated — PAN, MnT and PSN all on separate nodes, PSNs placed regionally, scaling to 50 PSNs.

Node group

A logical grouping of PSNs, usually those behind the same load balancer or in the same data centre. Members exchange heartbeats and session information, so if one PSN fails, a peer can issue the CoA to clear sessions that the failed node owned. Node group members must be able to reach each other, and the group is also how URL-redirect sessions survive a node failure.

PAN auto-failover

An optional feature where designated health-check nodes monitor the Primary PAN and automatically promote the Secondary after a configured number of failed checks. Requires at least one non-PAN node acting as health checker on each side. Without it, promotion is a manual action.

Load balancing PSNs

Common in large deployments, but with firm rules: the load balancer must send all packets of one session to the same PSN. Persistence is based on Calling-Station-Id or the RADIUS State attribute, never round-robin per packet, because EAP-TLS session state lives on one node. The source IP that ISE sees must also match the configured Network Device entry, so either preserve the source IP or define the load balancer itself as the NAD.

Interview angleA favourite trap. Explain why per-packet load balancing breaks EAP but not MAB — MAB is a single request-response, EAP is a stateful multi-round conversation.

ISE Messaging Service

The internal transport used from ISE 2.6 onward for syslog between nodes and for several internal services, replacing plain syslog. It is secured by its own certificate, which is why an expired ISE Messaging certificate causes nodes to stop reporting even though the deployment looks healthy.

Secondary node registration

Nodes join a deployment by being registered from the Primary PAN. The joining node's configuration is overwritten by the PAN's, its certificates must be trusted by the PAN, and the two must have matching time and resolvable DNS. “Registration fails” is nearly always one of: DNS, NTP, or a certificate the other side does not trust.

AAA Authentication, Authorization, Accounting

Authentication proves who you are. Authorization decides what you may do. Accounting records what you did. Keep them separate in your answers — a very large share of real ISE problems are authorization problems misdiagnosed as authentication problems.

RADIUS Remote Authentication Dial-In User Service

UDP-based, defined in RFC 2865/2866. Combines authentication and authorization in a single exchange: the Access-Accept carries both the yes and the permissions. Only the password attribute is encrypted; everything else travels in clear text, protected only by the Message-Authenticator integrity check.

Packet codes: Access-Request (1), Access-Accept (2), Access-Reject (3), Accounting-Request (4), Accounting-Response (5), Access-Challenge (11), CoA-Request (43), CoA-ACK (44), CoA-NAK (45).

TACACS+ Terminal Access Controller Access-Control System Plus

TCP 49, Cisco proprietary, and the right choice for administering network devices. Encrypts the entire packet body, and separates authentication, authorization and accounting into independent exchanges. That separation is what makes per-command authorization possible: every command the admin types can be checked against ISE before it runs.

Interview angle“Why TACACS+ instead of RADIUS for device admin?” Three reasons: full payload encryption, separated AAA allowing per-command authorization, and TCP giving reliable delivery and immediate failure detection.

Shared secret

The pre-shared key between NAD and ISE. It keys the Message-Authenticator, obscures the User-Password attribute, and encrypts the MPPE key attributes that carry session keys. A mismatch causes ISE to drop the packet silently — no authentication log is generated at all, which sends engineers hunting in the wrong place.

CoA Change of Authorization, RFC 5176

Lets ISE change or end an established session without the endpoint re-initiating. ISE acts as the CoA client, the NAD as the CoA server, on UDP 1700 for Cisco gear. The session is identified by Audit-Session-Id or Calling-Station-Id.

CoA types used by ISE:

  • Reauthenticate — rerun: re-evaluate policy with no new authentication. Fast, used by profiling.
  • Reauthenticate — last: repeat the last authentication method in full.
  • Port Bounce: shut/no-shut the port, forcing a DHCP renew. Used when a VLAN changes and the endpoint would otherwise keep a stale address.
  • Session Terminate: kill the session.
  • Port Shutdown: administratively disable the port.

On the switch this requires aaa server radius dynamic-author with a client statement for every PSN. A missing PSN there means profiling and posture quietly never take effect.

Audit-Session-Id

A unique session handle generated by the NAD and carried in a Cisco AV pair. It is the key that ties the switch's session table, ISE's Live Sessions, and any CoA together. In troubleshooting, capture it first.

RADIUS accounting

Start, Interim-Update and Stop records. More important in ISE than people expect: accounting carries Device Sensor profiling data, keeps the session alive in Live Sessions, and supplies the framed IP address that ISE needs for SGT-to-IP mapping and for posture redirect. If accounting is not configured on the NAD, profiling and posture degrade in confusing ways.

RadSec / RADIUS-DTLS

RADIUS carried inside TLS (TCP) or DTLS (UDP) on port 2083, using certificates instead of a shared secret. Solves the clear-text and weak-shared-secret problems, and is increasingly expected for traffic crossing untrusted networks or going to a cloud-hosted PSN.

NAD Network Access Device

Any switch, WLC, VPN headend or firewall that sends RADIUS to ISE. Must be defined in ISE under Network Devices with its IP address or range, shared secret, and optionally SNMP and TrustSec settings. An unknown NAD produces log message 11007 and the request is dropped.

NDG Network Device Group

Hierarchical grouping of NADs, by default Device Type and Location, with custom groups allowed. NDGs are the most common condition in policy set selection — for instance, one policy set for wireless, another for wired, another for VPN, each matched on Device Type.

03802.1X and access methods

The three access methods are 802.1X, MAB and WebAuth. Most designs use all three in a fallback chain, and interviewers like to probe the order and the failure behaviour.

IEEE 802.1X

Port-based network access control. Three roles: supplicant (endpoint software), authenticator (switch or WLC), authentication server (ISE). The authenticator relays EAP between the two without being able to read it.

EAPOL EAP over LAN

The L2 encapsulation on the access link. EtherType 0x888E, destination MAC 01:80:C2:00:00:03 (the PAE group address). Packet types: EAP-Packet (0), EAPOL-Start (1), EAPOL-Logoff (2), EAPOL-Key (3). Version 3 is required for MACsec/MKA.

Port states

Before authentication the port is unauthorized: only EAPOL, and control protocols such as CDP, LLDP and STP, are permitted. After a successful authorization it becomes authorized and normal traffic flows, subject to any dACL applied.

Host modes

  • single-host — one MAC address allowed on the port. Any second MAC causes a security violation.
  • multi-host — the first endpoint authenticates, every other MAC on the port rides on that authorization without authenticating. Weak; avoid.
  • multi-domain (MDA) — exactly one data endpoint and one voice endpoint, each authenticated separately. The standard choice for an IP phone with a PC behind it.
  • multi-auth — every MAC on the port authenticates independently and gets its own authorization. Needed behind an unmanaged hub or a virtualisation host.
Interview angleKnow that multi-auth and multi-host sound similar and behave completely differently. Multi-host is the insecure one.

MAB MAC Authentication Bypass

For endpoints with no supplicant: printers, cameras, badge readers, medical devices. The switch learns the source MAC and sends it to ISE as both username and password, with Service-Type = Call-Check. ISE matches it against the endpoint database or an identity group.

MAB is only as strong as your profiling, because a MAC address is trivially spoofed. Mitigate with profiling conditions in the authorization rule, anomalous behaviour detection, and restrictive dACLs or SGTs.

802.1X to MAB fallback

The switch sends EAP-Request/Identity and waits dot1x timeout tx-period (default 30 s) for a reply, repeating up to dot1x max-reauth-req times. Only then does it fall through to MAB. With defaults that is roughly 90 seconds of no network for a printer — which is why production configs either lower the timers or put MAB first using IBNS 2.0 ordering.

Deployment modes

  • Monitor mode — authentication open, everything is permitted regardless of result, failures are logged only. The mandatory first phase of every rollout.
  • Low-impact mode — still open, but a small pre-authentication ACL on the port permits only essentials (DHCP, DNS, PXE), and a successful authorization adds a dACL on top. Lets you enforce without black-holing anything you have not profiled yet.
  • Closed mode — no traffic at all before authorization. The end state.
Interview angleBeing able to describe this three-phase rollout is a strong signal of real deployment experience. Monitor to discover, low-impact to enforce safely, closed to finish.

IBNS 1.0 vs 2.0 Identity-Based Networking Services

IBNS 1.0 uses the legacy authentication interface commands with a fixed method order. IBNS 2.0 uses Cisco Common Classification Policy Language: class maps and policy-map type control subscriber, with service templates and explicit event handling. It allows concurrent 802.1X and MAB, differentiated failure handling, and far more control. Convert with authentication convert-to new-style, which is one-way.

Verification commands differ too: show authentication sessions for 1.0, show access-session for 2.0.

WebAuth web authentication

Credential collection through a browser, used for guests and as a last-resort fallback.

  • LWA (Local WebAuth) — the switch or WLC hosts the login page and sends the credentials to ISE. Simpler, but limited customisation and no CoA-driven flow.
  • CWA (Central WebAuth) — ISE hosts the portal. The endpoint first fails 802.1X or hits MAB, receives an authorization profile containing url-redirect and url-redirect-acl, is redirected to ISE, authenticates there, and ISE then sends a CoA that moves the session to its final authorization. This is the flow you should be able to narrate end to end.

Redirect ACL

An ACL configured locally on the NAD and referenced by name from the authorization profile. Its logic is often counter-intuitive: on IOS switches a permit entry means redirect this traffic and a deny means do not redirect. You must deny traffic to ISE itself and to DNS, or the redirect loops. On a WLC the semantics differ again.

Interview angle“Why does the guest portal not load?” is usually the redirect ACL, DNS, or the portal FQDN not resolving.

dACL downloadable ACL

An ACL defined centrally in ISE and pushed to the switch in the Access-Accept. The switch requests the ACL content by name in a separate RADIUS exchange, so you will see an extra Access-Request in a capture. Applies per session, so different endpoints on the same port get different ACLs. Requires an ip access-list extended placeholder and ip device tracking (or the IOS-XE equivalent) to resolve the source IP.

Dynamic VLAN assignment

Carried by three attributes together: Tunnel-Type = VLAN (13), Tunnel-Medium-Type = 802 (6), and Tunnel-Private-Group-ID holding the VLAN name or number. All three must be present. A VLAN change usually also needs a port bounce or DHCP renew, which is why Port Bounce CoA exists.

MACsec and MKA

IEEE 802.1AE encryption on the wire, keyed from the 802.1X session. The MSK produced by the EAP method becomes the CAK, which seeds MKA (802.1X-2010) to distribute SAKs. Requires EAPOL version 3 and switch hardware support. Downlink MACsec with EAP-TLS is the strongest wired access posture available.

EAP Extensible Authentication Protocol, RFC 3748

A framework, not an authentication method. Packet format is Code (Request 1, Response 2, Success 3, Failure 4), Identifier, Length, Type. Success and Failure are four bytes and carry no type, which is why a bare EAP-Success can never be trusted by itself.

EAP-TLS

Mutual certificate authentication, RFC 5216. Both sides present a certificate and prove possession of the private key. No password exists to phish or replay. Produces a 64-byte MSK derived from the TLS master secret, which becomes the PMK for wireless or the CAK for MACsec.

Operational cost is PKI: enrolment, renewal, revocation and trust distribution. Handshake size also means many round trips, because EAP-TLS fragments and each fragment is acknowledged individually.

EAP-TLS flags byte

The first byte of the EAP-TLS payload: L (0x80) length included, M (0x40) more fragments, S (0x20) start. The very first message from ISE is a bare 0x20. A receiver that gets a fragment with M set must reply with an acknowledgement — flags 0x00, no data — so each fragment costs a full round trip.

PEAP Protected EAP

Builds a TLS tunnel using a server certificate only, then runs an inner method — almost always MSCHAPv2 — inside it. Cheap to deploy because no client certificates are needed, but its security depends entirely on the supplicant actually validating the server certificate. If “Validate server certificate” is unticked, a rogue AP can harvest MSCHAPv2 challenge-response pairs.

Interview angle“Is PEAP secure?” The honest answer is: only if the supplicant is configured to validate the server certificate and pin the trusted CA and server name. That configuration dependency is PEAP's central weakness.

EAP-FAST and the PAC

Cisco's method using a Protected Access Credential instead of a server certificate to establish the tunnel. PACs can be provisioned in-band (anonymous or authenticated) or out-of-band. Largely superseded by TEAP, but still seen, and it introduced EAP chaining.

TEAP Tunnel EAP, RFC 7170

The modern answer to machine-and-user authentication. Inside one TLS tunnel it can run two inner methods in sequence — typically EAP-TLS for the machine and EAP-TLS or MSCHAPv2 for the user — and report both results to ISE. ISE can then authorize on the combination.

This is EAP chaining, and it solves a real problem: with plain EAP-TLS you authenticate the machine or the user, never both, so you cannot write a rule meaning “a corporate laptop with a corporate user logged in”. TEAP can. Supported natively from Windows 10 1809 onward.

Allowed Protocols

The ISE policy element that lists which EAP methods a policy set will accept, plus options such as EAP-TLS session resumption, the EAP fragment size (default 1002 bytes), and whether to allow weak or legacy methods. Referenced from the authentication policy. Narrowing it is a common hardening step — and a common cause of a device class suddenly failing.

Session resumption

Lets a returning endpoint skip the certificate exchange by presenting a session ID or ticket. Dramatically faster. The caution: a resumed session does not re-validate the certificate, so a revoked certificate can keep working until the cache times out.

MSK and key material

The TLS master secret is expanded into a 64-byte MSK and a 64-byte EMSK. ISE sends the MSK to the NAD inside the Access-Accept as MS-MPPE-Recv-Key and MS-MPPE-Send-Key, encrypted with the RADIUS shared secret. On wireless the first 32 bytes become the PMK, which the 4-way handshake turns into the PTK.

05Policy model

ISE policy is built from reusable elements assembled into policy sets. Describe the evaluation order correctly and most policy questions fall into place.

Policy Set

The top-level container. Each has a condition (commonly a Network Device Group, SSID or NAS-Port-Type), an Allowed Protocols object, and inside it an Authentication policy and an Authorization policy. Evaluation is first match wins, top to bottom, with a Default policy set always last.

Authentication policy

Inside a policy set. Rules match on attributes such as EAP method or Service-Type, and select an identity source — an identity store, a Certificate Authentication Profile, or an Identity Source Sequence. Also sets what to do if the user is not found, the process fails, or the store is unavailable: Reject, Continue, or Drop.

Continue is important: it lets an authentication that failed identity lookup still reach the authorization policy, which is how you build a rule that gives unknown endpoints a restricted profile instead of rejecting them.

Authorization policy

Evaluated after a successful authentication. Conditions can use certificate fields, AD group membership, endpoint profile, posture status, time and date, and the network device. Result is an Authorization Profile and optionally a Security Group. First match wins.

Authorization Profile

The result object: VLAN, dACL or Filter-Id, SGT, URL redirect, Session-Timeout and Termination-Action, interface template, reauthentication timer, and any raw RADIUS attributes you add. This is what becomes the Access-Accept.

Identity Source Sequence

An ordered list of identity stores tried in turn, with options for what to do if the user is not found in one. Used when the same policy must serve, for example, AD users, an LDAP directory and internal guest accounts.

Dictionaries and attributes

ISE groups available attributes into dictionaries: RADIUS (IETF and vendor, including Cisco AV pairs), Network Access, Session, Endpoints, CERTIFICATE, InternalUser, IdentityGroup, and one per joined AD domain. Knowing which dictionary holds an attribute is half of building a condition.

Conditions

Simple conditions test one attribute. Compound conditions join several with AND/OR. Saved conditions live in the Condition Studio library and are reusable — build them once rather than inline, so a change propagates. Time and Date conditions let you scope access to business hours.

Endpoint Identity Group

A container for endpoints, either static (you add MACs) or dynamically populated by a profiling policy. Built-in groups include Blocklist, RegisteredDevices, Profiled, Unknown. Used heavily in authorization conditions, especially for MAB.

Exception policy

A set of rules evaluated before the normal authorization rules, global or per policy set. Intended for temporary overrides — an incident response block, a short-term exemption — without disturbing the production rule order.

Policy evaluation order, end to end

  • Match the Policy Set by its condition.
  • Within it, match an Authentication rule; select Allowed Protocols and identity source.
  • Authenticate; retrieve identity attributes and group membership.
  • Evaluate Authorization Exception rules, then Authorization rules.
  • Return the matched Authorization Profile as the Access-Accept.
Interview angleIf asked why a user authenticated but got no access, walk this list and point at step four. Successful authentication plus default-deny authorization is the single most common “ISE is broken” ticket.

06Identity stores

Where ISE looks up the thing it just authenticated.

Internal Users and Internal Endpoints

ISE's own database. Internal Users hold local accounts with password policies and user identity groups. Internal Endpoints hold MAC addresses and all their profiled attributes. Guest accounts live here too.

Active Directory integration

ISE joins AD as a machine account. Key terms: a join point is one AD domain ISE is joined to (multiple join points are supported); a scope groups join points so policy can reference several domains together. ISE retrieves user and machine groups and attributes for use in authorization.

Requirements that trip people up: DNS must resolve the domain's SRV records, time must be within five minutes of the domain controllers, and the joining account needs rights to create a machine object. Troubleshoot with the AD test tools in the GUI and ad_agent.log.

Machine Access Restriction MAR

An older mechanism that caches a successful machine authentication for a period and requires a user authentication from the same MAC to match that cache. Fragile — it breaks with sleep, hibernation and wireless roaming — and is the reason TEAP and EAP chaining exist. Know it so you can explain why you would not choose it today.

LDAP, ODBC, RADIUS Token, RSA SecurID

External stores for non-AD directories, SQL databases, and one-time-password systems. ODBC is notable because it can run stored procedures, which lets you authenticate against an arbitrary back-end such as an asset database.

SAML identity provider

Used for portal logins — sponsor, guest, MyDevices — and for admin access, with ISE acting as service provider against an IdP such as Azure AD, Okta or ADFS. Enables single sign-on and MFA for those portals.

Certificate Authentication Profile CAP

Tells ISE which X.509 field becomes the username for a certificate-based authentication: Subject CN, Subject Alternative Name (DNS, Email or Other Name/UPN), or Subject Serial Number. Optionally performs a lookup against AD or LDAP, and optionally a binary comparison of the presented certificate against the one published on the AD object.

Picking the wrong field here produces a certificate that validates perfectly and then fails identity lookup, which logs as 22056 — a completely different signature from a TLS failure.

Identity rewrite

A CAP option that transforms the extracted username before lookup, for example stripping a domain prefix or a suffix. Useful when certificate naming does not match directory naming.

07Certificates and PKI

More ISE outages come from certificates than from policy. Expect detailed questions.

System certificates and their roles

Certificates ISE presents. Each is assigned one or more roles, per node:

  • Admin — the HTTPS GUI and API. Changing it restarts services on that node.
  • EAP Authentication — presented to supplicants during PEAP, EAP-TLS and TEAP. Every endpoint must trust its issuer.
  • Portal — guest, sponsor, BYOD, client provisioning. Needs a publicly trusted CA if guests use it.
  • pxGrid — mutual authentication with pxGrid clients.
  • RADIUS DTLS and SAML — for those specific services.
  • ISE Messaging Service — internal node-to-node transport.
Interview angle“What happens when the EAP certificate expires?” Every 802.1X authentication fails, because supplicants reject the server certificate. It is the highest-impact expiry in the deployment, and it tends to hit all nodes at once.

Trusted Certificates store and trust purposes

The CAs ISE trusts. Each entry carries explicit purposes:

  • Trust for authentication within ISE (node-to-node)
  • Trust for client authentication and Syslog
  • Trust for authentication of Cisco Services
  • Trust for certificate-based admin authentication

A CA present but without the client-authentication purpose will fail EAP-TLS while appearing to be installed. Pruning this list also shrinks the CertificateRequest message and reduces fragmentation.

SAN Subject Alternative Name

Modern clients validate the name against SAN, not CN. An ISE certificate's SAN must contain every FQDN by which it is reached — node FQDN, any load-balancer VIP name, and any portal FQDN. A missing SAN entry is a very common cause of a supplicant rejecting the EAP certificate or a browser warning on a portal.

ISE Internal CA

A built-in certificate authority used mainly for BYOD endpoint certificates. Hierarchy is a Root CA on the Primary PAN, a Node CA per PSN, and an Endpoint CA issuing to devices. It is not a general-purpose enterprise CA, and regenerating the root invalidates every certificate it issued.

SCEP and NDES

Simple Certificate Enrollment Protocol, the mechanism BYOD onboarding uses to request a certificate automatically. With a Microsoft CA this runs through NDES (Network Device Enrollment Service). ISE can act as a SCEP proxy on behalf of the endpoint.

CRL and OCSP

Revocation checking, configured per trust store entry. CRL downloads a list on a schedule. OCSP queries a responder per authentication, with a local cache. The key design decision is the Reject the request if OCSP returns UNKNOWN status setting — fail-closed or fail-open. A responder reachable from some PSNs but not others produces intermittent failures that follow the load-balancer hash.

EKU Extended Key Usage

The client certificate needs clientAuth (OID 1.3.6.1.5.5.7.3.2); the ISE EAP certificate needs serverAuth (1.3.6.1.5.5.7.3.1). A certificate issued from the wrong template often has neither, and fails in a way that looks like a trust problem.

Chain completeness

If a supplicant sends only its leaf certificate and the intermediate is in neither the message nor the ISE trust store, path building fails with an unknown-CA error. ISE does not chase AIA URLs by default. Load every intermediate into the trust store.

Device Sensor

A switch and WLC feature that collects CDP, LLDP and DHCP data locally and sends it to ISE inside RADIUS accounting. It removes the need for SPAN and helper-address plumbing, and is the recommended way to feed the profiler on Cisco access gear. Configure with device-sensor commands plus device-sensor accounting.

Interview angleMentioning Device Sensor unprompted signals design maturity, because the alternative probes are operationally expensive.

Profiling policy and Certainty Factor

Each profiling policy is a set of conditions, and each condition carries a Certainty Factor value. Matching conditions add their values together; when the total reaches the policy's Minimum Certainty Factor, the endpoint is assigned that profile. Policies are hierarchical — a generic parent such as Workstation with more specific children beneath it — and the most specific match with sufficient certainty wins.

Exception actions

A profiling policy can trigger an action rather than just a classification: assign to an identity group, raise an alarm, or run an NMAP scan. Used to escalate when something looks wrong.

Profiler Feed Service

Downloads new and updated device profiles from Cisco on a schedule, so newly released hardware is recognised without a software upgrade. Needs outbound internet access or an offline update file.

Context Visibility

The dashboard view of every known endpoint with all collected attributes, filterable and exportable. Where you go to answer “what is actually on my network?” and the fastest way to find an endpoint by MAC, IP, user or profile.

Anomalous Behaviour Detection

Detects a MAC address whose characteristics change in ways that suggest spoofing — for example, an endpoint profiled as a printer suddenly presenting a Windows DHCP fingerprint, or appearing on a different NAS port type. Can raise an alarm or trigger a CoA. The direct answer to “how do you stop someone spoofing a printer MAC?”

Endpoint attribute filter

Limits which collected attributes are written to the database, reducing replication load in large deployments. A scaling control rather than a feature.

Logical profile

A grouping of several endpoint profiles under one name, so a policy can reference, for example, IP-Phones covering every phone model rather than listing each. Keeps authorization rules short.

09Posture

Checking that an endpoint meets a compliance standard before granting full access. The flow, with its CoA, is the part to know cold.

Posture states

Unknown (no assessment yet), Compliant, Non-Compliant. Authorization rules are written against these, typically: Unknown gets redirected to provisioning, Non-Compliant gets a remediation VLAN or ACL, Compliant gets full access.

The posture flow

  • Endpoint authenticates (802.1X or MAB). Posture status is Unknown.
  • Authorization profile returns a redirect to the Client Provisioning Portal plus a redirect ACL, or in redirect-less mode relies on agent discovery.
  • The agent is installed or launched, discovers the PSN, and downloads the posture policy.
  • The agent runs the checks and reports the result to ISE.
  • ISE issues a CoA, policy is re-evaluated with the new posture status, and a new authorization profile is applied.
Interview angleThe CoA is the hinge of the whole flow. If an interviewer asks how the endpoint gets off the quarantine ACL, the answer is CoA, not a new authentication.

Agents

  • Cisco Secure Client ISE Posture Module (formerly AnyConnect) — the persistent agent, with the full check library.
  • Temporal Agent — dissolvable, runs once and removes itself. For contractors and unmanaged machines; a reduced check set.
  • Stealth mode — the agent runs as a service with no user interface, for environments where users should not see or interact with it.

Compliance Module

The OPSWAT-based library that knows about antivirus, antispyware, disk encryption, firewall and patch-management products. Versioned separately from the agent and updated far more often. A mismatched or outdated Compliance Module is a frequent cause of a check failing or a product not being detected.

Conditions, Requirements, Policies

The three-layer structure. A Condition is a single check (file exists, registry value, service running, AV definitions newer than N days, disk encrypted, USB blocked). A Requirement binds one or more conditions to an operating system and a remediation action. A Posture Policy applies requirements to an identity group and OS.

Remediation

What happens when a requirement fails: launch a program, update AV definitions, trigger a patch install, show a message with a link, or simply report. Can be automatic or user-initiated, mandatory, optional or audit-only.

Client Provisioning Policy

Decides which agent package, profile and compliance module an endpoint receives, based on OS, identity group and other conditions. Separate from posture policy — provisioning delivers the agent, posture decides what it checks.

Redirect-less posture

Posture without a URL redirect ACL, supported from ISE 2.2. The agent discovers its PSN through a configured Call Home List or via enroll.cisco.com. Valuable where the NAD cannot do URL redirection — third-party switches, some cloud and VPN topologies.

PRA, posture lease and grace period

Periodic Reassessment re-checks a compliant endpoint at an interval. Posture lease lets an endpoint skip reassessment for a set time after passing, reducing load. Grace period gives a newly non-compliant endpoint continued access for a window before enforcement, which is how you roll posture out without a flood of help-desk calls.

10BYOD

Getting a personal device a certificate and a supplicant configuration, without an administrator touching it.

Native Supplicant Provisioning NSP

The onboarding wizard that configures the device's built-in supplicant and installs a certificate. On Windows and macOS this runs through the Cisco Network Setup Assistant; on iOS it uses the Apple over-the-air profile mechanism; on Android it uses the Network Setup Assistant app.

Dual-SSID vs single-SSID onboarding

  • Dual-SSID — the user joins an open or guest SSID, is redirected to the BYOD portal, onboards, then moves to the secure SSID using the new certificate. Easiest for users to understand.
  • Single-SSID — the user joins the secure SSID with PEAP and AD credentials, is redirected and onboarded, then reconnects to the same SSID with EAP-TLS. Fewer SSIDs, but the supplicant must support a mid-session change.

My Devices Portal

Self-service portal where users register devices, name them, and mark one lost or stolen, which moves it to the Blocklist identity group and revokes its certificate. Reduces help-desk load and is a good answer to “how do you handle a lost BYOD device?”

BYOD registration attributes

Onboarded endpoints gain attributes such as BYODRegistration and membership of the RegisteredDevices identity group, plus a link to the owning user. Authorization rules use these to separate a registered personal device from an unknown one.

Certificate Provisioning Portal

Issues a certificate to a device that cannot run the full onboarding flow — a user requests a certificate manually, or an administrator does a bulk request from a CSV. Useful for appliances and for platforms the wizard does not support.

MDM / UEM integration

ISE can query an MDM such as Intune, Workspace ONE or MobileIron for device attributes — registration status, compliance, jailbreak status, disk encryption, PIN lock — and use them in authorization. It can also trigger a remote wipe or lock. Complements posture: MDM covers mobile, the posture agent covers desktop.

11Guest access

Three portal patterns, and the sponsor model behind them.

Hotspot portal

No credentials. The user accepts an acceptable use policy, optionally enters an access code, and is granted access. Simplest pattern; used in retail and public spaces. Access is tied to the device MAC rather than to a person, so it gives you the weakest accountability.

Self-registered portal

The guest creates their own account, optionally requiring sponsor approval, SMS or email verification before it activates. Balances convenience against traceability, and is the most common enterprise choice.

Sponsored portal

An employee creates the guest account in advance through the Sponsor Portal and passes the credentials to the visitor. Strongest accountability, because every guest account has a named sponsor.

Guest Type

Defines account lifetime, maximum simultaneous logins, allowed login hours, password policy and whether the account can be extended. Previously called guest roles. Authorization rules frequently match on guest type to give contractors more access than visitors.

Sponsor Group

Controls which employees may create guest accounts, which guest types they may create, and whose accounts they may see and manage. Mapped to AD groups.

Guest flow and CoA

The endpoint hits MAB, gets a redirect to the guest portal, the guest logs in, and ISE issues a CoA to re-evaluate the session with the guest identity now known. Identical in shape to the posture and CWA flows — one pattern, three uses.

AUP and account purge

The Acceptable Use Policy page can be shown on first login or every login, and acceptance is logged. The purge policy deletes expired guest accounts on a schedule, which matters because guest accounts otherwise accumulate indefinitely and count against database size.

12TrustSec and segmentation

Policy based on role rather than IP address. Increasingly the centre of gravity in ISE interviews.

SGT Security Group Tag

A 16-bit value representing a role, assigned to traffic at its ingress point. Assigned dynamically by an ISE authorization rule, or statically mapped to an IP, subnet, VLAN or port. SGT 0 is Unknown; SGT 2 is conventionally TrustSec Devices.

The point is decoupling policy from addressing: a contractor is a contractor whether they are on 10.1.1.0/24 or 172.16.9.0/24, so the policy survives renumbering and does not need an ACL per subnet.

SGACL Security Group ACL

The enforcement object. Applied at egress, where the destination SGT is known, based on the source SGT and destination SGT pair. Defined centrally in ISE and downloaded by the enforcing device.

TrustSec policy matrix

The grid in ISE with source SGTs down one axis and destination SGTs across the other, each cell holding the SGACL for that pair. Also holds a default policy for unmatched cells — which is where you decide whether your segmentation is default-permit or default-deny.

Inline tagging CMD

The SGT carried in a Cisco Meta Data field inserted into the L2 frame, hop by hop. The native method, but it requires hardware support on every link in the path.

SXP SGT Exchange Protocol

TCP 64999. Carries IP-to-SGT mappings to devices that cannot do inline tagging. Operates in speaker and listener roles; ISE can be either and often acts as a mapping aggregator and reflector. Scaling SXP peerings is a real design constraint in large networks.

Interview angle“When do you use SXP instead of inline tagging?” When the data path crosses equipment that cannot carry the CMD field — older switches, most WAN links, and many firewalls.

Environment data

The SGT name-to-number table and the device's own SGT, downloaded from ISE by a TrustSec-enabled NAD. Without it, a device can enforce numbers but cannot display names, and policy downloads fail.

PAC for TrustSec

Historically a TrustSec device authenticated to ISE using a PAC obtained over EAP-FAST before it could download environment data and policy. Newer releases support PAC-less operation using RADIUS with a shared secret, which simplifies deployment considerably.

Security Group Firewall

SGT-aware rules on a firewall such as ASA or Secure Firewall, letting you write firewall policy in terms of roles. The firewall learns mappings through SXP or pxGrid.

13pxGrid and integrations

How ISE shares what it knows, and acts on what others tell it.

pxGrid Platform Exchange Grid

A publish-subscribe bus for security context. ISE publishes session information — user, device, IP, SGT, posture — and subscribers consume it. Clients authenticate with certificates and must be approved in ISE. pxGrid 1.0 used XMPP; pxGrid 2.0 uses WebSocket with STOMP and a REST API, on 8910 and 443.

Topics

Named channels a client subscribes to: SessionDirectory, TrustSecMetaData, EndpointProtectionService, ANCConfig, Radius failures, and others. A client subscribes only to what it needs.

ANC Adaptive Network Control

The mechanism for acting on a session from outside ISE, formerly EPS (Endpoint Protection Service). An ANC policy applies Quarantine, Shut_Down or Port_Bounce to an endpoint, enforced by CoA. Triggered from the ISE GUI, the API, or by a pxGrid partner.

Rapid Threat Containment

The umbrella name for the pattern: a security product detects a compromised host, calls ISE over pxGrid or the API, ISE applies an ANC policy, and the endpoint is quarantined within seconds without a human in the loop.

Interview angleA strong answer connects three things: detection in another product, pxGrid or ERS as the integration path, and CoA as the enforcement mechanism.

TC-NAC Threat Centric NAC

Brings vulnerability and threat data into authorization. Vulnerability adapters for Qualys, Rapid7 and Tenable supply CVSS scores; threat adapters supply indicators from Cisco Secure Endpoint and Cognitive Threat Analytics. You can then write a rule such as “CVSS above 7 moves the endpoint to a remediation group”.

ERS API External RESTful Services

REST API on TCP 9060 for configuration objects: endpoints, identity groups, network devices, guest accounts. Must be enabled explicitly and uses a dedicated admin role. The usual target for automation scripts. ISE also offers Open API and MnT APIs for operational data.

Common integrations

  • Secure Firewall Management Center — user and SGT identity for firewall policy.
  • Secure Network Analytics (Stealthwatch) — user context on flows, and quarantine actions back to ISE.
  • Secure Web Appliance — transparent user identification for web policy.
  • Catalyst Center — ISE as the policy engine for SD-Access group-based policy.
  • SIEM platforms — syslog from MnT, or pxGrid for context enrichment.

14Device administration

TACACS+ for controlling who can log into your switches and what they can type.

Device Admin Policy Sets

Entirely separate from network access policy sets, with their own conditions, identity sources and results. The TACACS+ service must be enabled per PSN, and the deployment needs a Device Admin license.

TACACS Profile shell profile

The authorization result for a login session: privilege level (default and maximum), session timeout, and custom attributes. Privilege 15 for full administrators, privilege 1 for read-only, with custom levels in between.

Command Set

A list of permitted or denied commands with their arguments, evaluated on every command the administrator enters. Supports wildcards and a default permit-or-deny. This is what enables a help-desk role that can run show commands and clear counters but nothing else.

Per-command authorization and accounting

Because TACACS+ separates the three A's, the device asks ISE about each command before executing it, and logs each one afterwards. The accounting record is the audit trail auditors ask for. RADIUS cannot do this.

TACACS Live Logs

A separate Live Log view for device administration, showing authentication, authorization and accounting events with the commands entered. First place to look when an admin reports being unable to run a command.

Device admin fallback

Always configure a local fallback method, for example aaa authentication login default group ISE-TACACS local, and keep a local account. Otherwise losing ISE or the network path to it locks you out of every device simultaneously. Expect to be asked about this.

Live Logs shows authentication events as they happen. Live Sessions shows currently active sessions and is where you launch a CoA by hand. The Steps column inside a detailed authentication report lists every EAP message with its step code, so you can see exactly where a conversation died.

Diagnostic tools

Useful CLI

Backup and patching

Two backup types: configuration (from the PAN, holds policy and certificates) and operational (from MnT, holds logs). Both go to a defined repository. Patches install on the PAN first and then roll to the other nodes, which restarts services on each — plan a window.

The diagnostic shortcut for EAP-TLS

  • Fails before any certificate appears → cipher or TLS version mismatch.
  • Fails right after the ISE certificate → supplicant trust problem.
  • Fails right after the client certificate → ISE trust store, chain or revocation problem.
  • Clean handshake then failure → identity resolution, not cryptography.
  • Clean authentication, wrong access → authorization policy.

17Self-test

Answer out loud before opening each one. Questions are phrased the way interviewers actually ask them.

Walk me through what happens from the moment a laptop is plugged into a 802.1X port.

Port is unauthorized, passing only EAPOL and control protocols. Switch sends EAP-Request/Identity, or the supplicant sends EAPOL-Start. The identity response is wrapped into a RADIUS Access-Request with the EAP-Message attribute and sent to the PSN. ISE selects a policy set, matches an authentication rule, and returns an Access-Challenge starting the EAP method. The method runs to completion with the switch relaying every message. ISE then evaluates authorization and returns an Access-Accept carrying the result attributes and, for key-generating methods, the MPPE key attributes. The switch authorizes the port and applies the dACL, VLAN or SGT.

What is the difference between authentication and authorization failing, and how do you tell from the logs?

An authentication failure means ISE could not verify the credential or resolve the identity — codes such as 12514, 22056 or 24408. An authorization failure means the identity was verified but no rule granted useful access, so the session lands on the default rule. In Live Logs the giveaway is a green successful authentication whose authorization profile is DenyAccess or a limited profile. The detailed report shows which rule matched.

Why does EAP-TLS need so many RADIUS round trips?

Because the TLS handshake is larger than one EAP packet, EAP-TLS fragments it, and each fragment with the More bit set must be acknowledged with a bare EAP-TLS Ack before the next is sent. Fragment count is driven by the ISE EAP fragment size, the Framed-MTU, the certificate chain sizes, and the length of the CA list in CertificateRequest. Shrinking the trust store and using ECDSA certificates both cut it down.

A printer stopped working after you enabled 802.1X. What happened and how do you fix it properly?

The printer has no supplicant, so the switch waits through the full dot1x timeout and retry cycle before falling back to MAB — roughly 90 seconds with defaults. Fix it properly by profiling the printer and writing a MAB authorization rule matched on the printer profile, not just the MAC, and by using IBNS 2.0 so MAB and dot1x can run concurrently rather than in a slow sequence. Tighten the result with a dACL or SGT, because MAB alone is spoofable.

How would you stop someone spoofing that printer's MAC address?

Layer defences: profile the endpoint and require the profile in the authorization condition, enable Anomalous Behaviour Detection so a change in fingerprint or port type raises an alarm or triggers CoA, restrict what the printer VLAN or SGT can reach so a spoofed session gains little, and where the device supports it move to certificate-based authentication instead of MAB.

Explain the Central WebAuth flow.

The endpoint fails 802.1X or matches MAB. ISE returns an authorization profile containing url-redirect and url-redirect-acl. The switch intercepts HTTP and redirects the user to the ISE guest portal. The user authenticates there. ISE then issues a CoA reauthenticate against the session, policy is re-evaluated with the guest identity known, and a new Access-Accept applies the final access. The same redirect-plus-CoA shape is used by posture and BYOD.

What does a node group give you?

PSNs in a node group share session state and heartbeats. If one PSN fails, a peer can issue the CoA for sessions the failed node owned, so redirect-based flows are not stranded. It is about session survivability, not load balancing.

Why can you not load-balance RADIUS per packet?

EAP is a stateful multi-round conversation and the TLS state lives on one PSN. A packet landing on a different node has no matching state and the handshake dies with no clear error. Persistence must be on Calling-Station-Id or the RADIUS State attribute. MAB, being a single request-response, does not have this problem.

What is EAP chaining and which method provides it?

Authenticating the machine and the user within a single EAP conversation and reporting both results, so authorization can require both. TEAP provides it natively, and EAP-FAST provided it earlier. Plain EAP-TLS cannot, which is why the older workaround was Machine Access Restriction — a cache-based approach that breaks with sleep and roaming.

How does posture know when to let the endpoint out of quarantine?

It does not decide locally. The agent reports the assessment result to ISE, ISE changes the session's posture status to Compliant, and ISE issues a CoA. Policy is re-evaluated with the new status and a new authorization profile is applied. The CoA is the hinge.

What is the difference between SXP and inline tagging?

Inline tagging carries the SGT inside the frame in a Cisco Meta Data field, hop by hop, and needs hardware support on every link. SXP is a TCP control-plane protocol on 64999 that distributes IP-to-SGT mappings to devices that cannot carry the tag inline. SXP tells a device what tag an address has; inline tagging puts the tag on the traffic itself.

Your guest portal shows a certificate warning. Where do you look?

The portal certificate, specifically whether its SAN includes the FQDN that guests actually resolve, and whether it is issued by a publicly trusted CA — guests will not have your internal root. Also confirm the portal FQDN resolves in the guest DNS and that the redirect ACL permits DNS and traffic to ISE.

What breaks if the Primary PAN is down for a day?

Authentication continues, because PSNs serve from their local copy of the configuration. What stops is configuration change, and anything needing a central database write — new guest accounts, BYOD registration, certain endpoint updates. Reporting continues through MnT. You promote the Secondary PAN manually unless auto-failover is configured.

How do you roll out 802.1X across a campus without breaking it?

Three phases. Monitor mode first, with open authentication and no enforcement, to discover every endpoint and build profiles. Then low-impact mode, with a small pre-auth ACL and dACLs applied on success, so enforcement starts without black-holing unknown devices. Finally closed mode once the exception list is empty. Pair it with Device Sensor for profiling data and a clear MAB strategy for the devices that will never have a supplicant.

Why TACACS+ rather than RADIUS for device administration?

TACACS+ encrypts the entire packet body rather than just the password, separates authentication from authorization so each command can be checked individually, and runs over TCP so failures are detected immediately. Per-command authorization and accounting is the capability auditors ask for, and RADIUS cannot provide it.

Describe Rapid Threat Containment.

Another security product detects a compromised endpoint, calls ISE through pxGrid or the ERS API, ISE applies an ANC policy such as Quarantine, and ISE enforces it with a CoA against the live session. The endpoint is isolated in seconds with no manual step.

What does Certainty Factor mean in profiling?

Each condition in a profiling policy carries a certainty value. Matching conditions accumulate, and when the total reaches the policy's Minimum Certainty Factor the endpoint is assigned that profile. Policies are hierarchical, so a general profile can be refined by a more specific child with a higher threshold.

An authentication shows 5440, endpoint abandoned EAP session. What are your first three checks?

One, does the supplicant trust the ISE EAP certificate — check the trusted root in the profile and whether the SAN matches. Two, fragmentation — take captures on both legs and see whether it always dies at the same fragment, which points at MTU or a path dropping fragmented UDP. Three, timers and load balancing — confirm the session is not being moved between PSNs mid-handshake.

What is the difference between a dACL and an SGT-based policy?

A dACL is an IP-based access list applied to one session at the access port. An SGT tags the traffic with a role and enforcement happens at egress through SGACLs, based on the source and destination group pair. The dACL scales with the number of subnets you must enumerate; the SGT approach scales with the number of roles, which is usually far smaller and survives renumbering.

Where does ISE get the endpoint IP address, and why does it matter?

Usually from the Framed-IP-Address in RADIUS accounting, or from DHCP and SNMP probes, or from the device tracking table via the NAD. It matters because posture redirect, SGT-to-IP mapping for SXP, and dACL source resolution all depend on it. This is why missing RADIUS accounting causes problems that look unrelated to accounting.
